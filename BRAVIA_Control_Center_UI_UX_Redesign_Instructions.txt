BRAVIA CONTROL CENTER — COMPLETE UI / UX REDESIGN INSTRUCTION SET

PROJECT

Sony BRAVIA KD-55X8000H Console v3.0 Ultra

PURPOSE

Redesign the entire existing desktop web application into a polished,
professional “BRAVIA Control Center” for managing, optimizing, and
customizing a Sony Android TV over ADB.

The existing functionality should be preserved wherever possible. This
is primarily a UI architecture, navigation, UX, interaction, hierarchy,
and design-system redesign.

IMPORTANT: - Do NOT throw away working functionality merely to change
the UI. - Do NOT fabricate hardware capabilities or claim a tweak works
unless the existing implementation actually supports it. - Preserve all
existing ADB commands, package IDs, system-property logic, launcher
controls, APK installation, remote controls, network controls, debloat
functionality, audit functionality, and logs. - Separate user-friendly
concepts from technical implementation details. - Technical/experimental
controls must live in Advanced areas. - Build reusable components
instead of redesigning each page independently. - The final product
should feel like a premium desktop hardware-management utility, not an
HTML developer dashboard.

PRODUCT POSITIONING

Product name: BRAVIA Control Center

Subtitle: Desktop power-user console for Sony BRAVIA TVs

Primary design character: Premium hardware control center Dark Technical
but approachable Professional Calm High information density without
visual clutter

The existing dark theme should be retained as the foundation, but
refined: - Very dark navy/black background - Slightly lighter navy
surfaces - Subtle borders - Electric Sony-like blue as the primary
accent - Green ONLY for actual healthy/success/connected states - Amber
for warnings - Red ONLY for destructive or dangerous actions -
Gray/neutral for secondary actions - Reduce excessive neon colors -
Reduce unnecessary borders - Increase whitespace and hierarchy - Avoid
making every card look identical

============================================================ 43.
IMPORTANT IMPLEMENTATION RULES FOR THE IDE
============================================================

Before changing code:

1.  Inspect the entire existing project.
2.  Identify framework, routing, state management, component library,
    CSS architecture, backend/API/ADB layer, and existing commands.
3.  Identify every existing action and ensure it remains connected.
4.  Do not replace working backend logic with mock implementations.
5.  Do not hard-code fake device data.
6.  Do not remove functionality just because it is technical.
7.  Refactor repeated UI into reusable components.
8.  Preserve the existing ADB connection architecture.
9.  Preserve existing package IDs and commands.
10. Preserve existing error handling where it is correct.
11. Improve error handling where it is unclear.
12. Keep all destructive operations protected.
13. Use the existing device state as the source of truth.
14. Avoid duplicated API/ADB calls when shared state can be reused.
15. Avoid polling excessively.
16. Do not claim an optimization has succeeded until the command
    actually succeeds.
17. Refresh affected state after a successful modification.
18. Log important actions in the activity timeline.
19. Keep technical command output accessible through the terminal
    drawer.
20. Do not remove raw technical information; move it into
    Advanced/Technical sections.

============================================================ 44. FINAL
PRODUCT PHILOSOPHY
============================================================

The old application is:

    "A collection of powerful TV modification tools."

The redesigned application should feel like:

    "A complete control center for my BRAVIA."

The user should be able to open the application and immediately
understand:

    My TV is connected.
    My TV is healthy.
    Here is what needs attention.
    Here is my active profile.
    Here are the safest useful optimizations.
    Here is where I manage apps and launchers.
    Here is where advanced users can access deeper controls.

The guiding hierarchy is:

    SIMPLE
      ↓
    PROFILE
      ↓
    SETTING
      ↓
    ADVANCED
      ↓
    RAW TECHNICAL DETAILS

Do not force the user to start at the bottom.

The application should hide complexity without removing power.

FINAL TARGET

The finished product should visually and behaviorally resemble a premium
desktop utility such as a modern system-management application:

    BRAVIA CONTROL CENTER
